📖 The Complete Beginner's Guide to Git & GitHub Pull Requests (PR)

Welcome! This guide explains what a Pull Request (PR) is, why software teams use them worldwide, how the complete PR workflow operates step-by-step, and how we created Pull Request #1 for this repository.

1. What is a Pull Request (PR)?

Imagine you and your teammate are co-authoring a book. Instead of directly overwriting your teammate's original pages, you make a draft copy, write your new chapters or fix typos, and then ask:

"Hey! I improved these 3 sections. Please review my changes and pull them into the main book if you approve!"

In software development, that formal review request is called a Pull Request (PR). You are requesting that the repository maintainer pull (merge) your code edits into the primary codebase.

2. Why Do Developers Use Pull Requests?

  • Code Safety: Prevents unreviewed code from breaking the production branch (main).
  • Peer Review: Team members inspect line-by-line code differences (Diffs) before merging.
  • Collaboration & Discussion: Developers can comment on specific lines of code, ask questions, or suggest optimizations.
  • Version Tracking: Maintains a complete audit trail of feature additions, bug fixes, and author credits.

Step 1: Forking (Your Personal Copy)

Creating your personal copy of a repository under your GitHub account (e.g. forking Ghostofzenin08/Game--Development-In-Python to parthongit89/Game--Development-In-Python).

Step 2: Branching (Isolated Workspace)

Creating a dedicated feature branch so work remains isolated from the main branch:

git checkout -b refactor-galaxy-shooters

Step 3: Committing & Pushing (Saving Changes)

Saving work locally and pushing to your personal GitHub fork:

git add . && git commit -m "Refactor Galaxy Shooters controls & HUD" && git push origin feature-branch

Step 4: Opening the Pull Request

Navigating to GitHub, clicking "Compare & Pull Request", and providing a comprehensive description of changes.

Step 5: Code Review & Merging

The maintainer reviews diffs, runs tests, approves the PR, and clicks "Merge Pull Request".

4. Git Command Cheat Sheet

Action Command Description
Check Status git status Displays modified or uncommitted files
Create Branch git checkout -b <name> Creates and switches to a new branch
Stage Changes git add . Stages all working directory changes
Commit Changes git commit -m "Message" Saves staged changes with a commit message
Push Branch git push origin <name> Uploads local branch to remote repository

2. Particle & Flame Stream Engine

The starfighter thruster effect uses a multi-stage dual-nozzle particle generator:

# Dual-nozzle thruster coordinates left_nozzle = (self.x + 12, self.y + self.height) right_nozzle = (self.x + self.width - 12, self.y + self.height) # Spawn multi-colored plasma flame particles (orange, cyan, white)

3. Universal Display Scaling

The game renders to a logical 1280x720 internal surface, which is hardware-scaled with smooth bilinear interpolation to fit any screen resolution (1080p, 1440p, 4K) while maintaining strict aspect ratios.
